## 修复计划

### 优先级排序

| 优先级 | 问题 | 影响 | 修复方案 |
|--------|------|------|----------|
| **P0** | 多模态覆盖 0.7% | 模型不会处理图片 | 修复 `_build_user_message` 函数 |
| **P0** | 金标完备率 0% | GRPO 训练无法进行 | grpo 添加 gold，eval 添加 n_ref |
| **P1** | 4 个工具未使用 | 模型不会调用这些工具 | 添加 ocr/ask_user/transfer_to_human 场景 |
| **P1** | 数据量 30k | 4B 模型可能过拟合 | SFT 减少到 10-12k |
| **P2** | 验收脚本逻辑 | 检查不准确 | 修正检查逻辑 |

### 修复顺序

1. **修复多模态覆盖**（P0）
   - 检查 `_build_user_message` 函数
   - 确保有图片的轨迹 user 消息包含图片

2. **修复金标完备率**（P0）
   - grpo 数据添加 `gold` 字段
   - eval 数据添加 `n_ref` 字段

3. **添加未使用的工具**（P1）
   - 添加 OCR 场景：用户发截图，模型调用 ocr 提取信息
   - 添加 ask_user 场景：用户信息不全，模型询问
   - 添加 transfer_to_human 场景：情绪失控、投诉升级

4. **调整数据量**（P1）
   - SFT: 17k → 10-12k
   - GRPO: 8k → 5k
   - anti: 3.6k → 2k

5. **修正验收脚本**（P2）
   - 修正实体合法性检查逻辑
   - 修正金标完备率检查逻辑
