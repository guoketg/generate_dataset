## 模型切换: 27B 重型 -> 4B 轻量
- 原因: 原 Teacher 模型 Qwen3.8-27B-Q4_K_XL(17GB) 单序列推理过慢(~12.7 batch/h),
  且 Qwen3.5 的 thinking 机制导致每批 JSON 解析失败重试频繁。
- 改用: `unsloth/Qwen3.5-4B-Q4_K_M.gguf`(2.6GB), 经 hf-mirror 镜像下载至
  `models/Qwen3.5-4B-Q4_K_M.gguf`。
- 验证: 4B 直接输出干净标准 JSON 数组, 无 thinking 废话, 解析成功率大幅提升。

## 架构(本机约束)
- 硬件: H200 MIG 2g.35gb, 约 33GB 显存。
- llama_cpp 0.3.35 **单实例单 slot 串行**: server 端并发请求会排队, 不线性加速。
- 多实例 OOM(2x17GB>33GB), 故仅单实例。真正提速来自换小模型。
- 服务: `run_teacher.py` 起 OpenAI 兼容 server (端口 8001, 4B 模型)。
  (端口 8000 为已停用的旧 27B server 残留进程, 见下方"待清理"。)
- 客户端: `gen_products.py` 经 `llm_client.TeacherLLM(base_url=...)` HTTP 调用,
  `extract_json_array` 已增强(raw_decode 容错, 应对截断/格式瑕疵)。
